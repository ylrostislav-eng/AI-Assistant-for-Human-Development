# Разбор угроз на конец Phase 0 (часть P0-04)

Дата: 2026-09-15. Разбирается то, что действительно написано: конфигурация, пул PostgreSQL, маршруты health, команда миграций и прототип изоляции. Приложения iOS, аутентификации и доменных таблиц ещё нет, поэтому большая часть таблицы рисков из [09. Безопасность](09-security-and-operations.md) относится к будущему коду и здесь не пересказывается.

Разбор — чтение кода и проверки на работающей системе. Это не аудит и не тест на проникновение.

## Закрыто

**Роль подключения к базе.** Прототип изоляции показал, что под владельцем таблиц или суперпользователем RLS не действует — молча, без ошибок. Приложение в разработке подключается именно такой ролью. Добавлена проверка при запуске: в production запуск отклоняется, в разработке печатается предупреждение. Проверено вживую: `NODE_ENV=production` под ролью `system` не поднимает сервер и печатает причину; в разработке сервер стартует с предупреждением. Ослабление проверки в разработке сознательное — иначе её начнут обходить.

**Секреты.** Конфигурация только из переменных окружения, отсутствие `DATABASE_URL` останавливает запуск. `.env` в `.gitignore`, `npm run scan:secrets` с положительным контролем. Причина ошибки подключения не попадает в тело ответа readiness — проверено тестом.

**Ошибки сервера.** Живая проверка показала в ответе 500 текст ошибки PostgreSQL с именем колонки: разведка схемы без усилий. Добавлен обработчик, возвращающий `internal_error` без подробностей; ошибки со статусом ниже 500 описывают запрос клиента и скрывать их не нужно.

**Зависимости.** `npm audit` — 0 уязвимостей на дату проверки. Production-зависимостей верхнего уровня две: `fastify`, `pg`. Малое дерево зависимостей — осознанное решение, а не случайность: каждая новая библиотека расширяет поверхность атаки.

## Открыто, с конкретными требованиями

**Аутентификация — закрыта половина.** Доступ по умолчанию закрыт на уровне приложения: проверка access-токена вешается раньше маршрутов, публичные пути перечислены явным списком (`PUBLIC_PATHS`). Забытый маршрут теперь перестаёт работать, а не остаётся открытым. Остаётся незакрытым главное: проверка Apple identity token не реализована, вход выполняется по синтетической личности и только при `DEV_AUTH_ENABLED` вне production.

**RLS у каждой таблицы отдельно.** Механизм проверен, но включается он для каждой таблицы своими `ENABLE`, `FORCE` и политикой. Требование к P1-01: проверка, которая перечисляет таблицы с пользовательскими данными без RLS и падает на найденной. Без неё забытая таблица не обнаруживается ничем.

**Ограничения запросов.** Лимит тела запроса — значение Fastify по умолчанию (1 МБ), ограничений частоты и бюджетов нет. До появления маршрутов ИИ это неважно, вместе с ними становится обязательным (docs/09, строка про массовые запросы).

**Логов нет совсем.** Логирование выключено целиком, поэтому личный текст в логи попасть не может, но и следов обращения к данным не остаётся. Требование: вводить логи сразу редактированными — идентификаторы команд и коды ошибок, без заголовков авторизации и содержания целей.

**TLS вне приложения.** Приложение слушает HTTP; шифрование канала — задача reverse proxy. В наброске compose порты привязаны к localhost, наружу ничего не выставляется.

**Раскрытие в `/health`.** Маршрут отдаёт имя окружения и время работы процесса. Риск незначительный, но при открытии наружу это лишние сведения; при появлении публичного адреса оставить снаружи только код ответа.

## Чего разбор не проверял

Устойчивость к подделке токенов (их нет), prompt injection (нет ИИ), изоляцию в worker (его нет), поведение за внешним пулом соединений, восстановление из резервной копии, а также любые свойства iOS-приложения.
