## Повторяемые команды

Из корня репозитория:

```bash
python3 scripts/check_environment.py
python3 scripts/check_environment.py --profile docs
python3 scripts/check_environment.py --profile node
python3 scripts/check_environment.py --profile ios
python3 scripts/check_environment.py --json
python3 docs/validation/check_architecture.py
```

`inventory` сообщает наблюдения; отсутствующий Swift не делает полный список ошибкой. Другие profiles проверяют свой минимальный набор CLI. Exit code 0 — выбранные CLI-условия выполнены; 2 — не выполнены. `ios` на Linux ожидаемо возвращает 2. Ни один profile не заявляет успешную сборку приложения.

Скрипт использует только Python standard library, фиксированные команды версий без shell, timeout 5 секунд на инструмент. Он не устанавливает зависимости, не запускает контейнеры, не подключается к БД и не читает ключи API. stdout в JSON подходит для будущей CI-диагностики.

## Выбор версий следующего шага

Node 22 остаётся LTS на дату проверки; линия 24 тоже LTS. Для начала можно использовать установленную 22.23.2, а окончательный pin выбирать вместе с package compatibility smoke и проверкой актуального patch. Это не обещание, что данная локальная patch-версия будет подходить для будущего публичного релиза. [Node.js Releases](https://nodejs.org/en/about/previous-releases)

Архитектурный backend candidate — Fastify 5. Его LTS-таблица включает Node 22; конкретные package versions всё равно должны пройти install/typecheck/smoke, прежде чем появятся lockfiles. [Fastify LTS](https://fastify.dev/docs/latest/Reference/LTS/)

Для PostgreSQL нужен отдельно запущенный тестовый сервер поддерживаемой версии, выделенные test credentials и успешная транзакция/миграция. Версия локального клиента не определяет версию сервера.

Для iOS нужен доступный Mac: проверить `xcodebuild -version`, SDK/simulator runtimes, сборку минимального SwiftUI app и deployment target iOS 17+. На основании Linux-аудита нельзя зафиксировать работающий Xcode/Swift/GRDB набор.

## P0-01b: зафиксированный toolchain

Package manager — **npm workspaces**. Выбран потому, что npm поставляется с Node и уже присутствует в обеих проверенных средах; pnpm/yarn потребовали бы отдельной установки на сервере ради того же результата на одном backend-пакете. Решение пересматривается, когда появятся Swift-пакеты и второй JS-пакет в `packages/`.

Версии зафиксированы точными пинами (без `^` и `~`), воспроизводимость обеспечивает `package-lock.json` в корне.

| Пакет | Пин | Проверено |
|---|---|---|
| Node.js | `>=22.22.0 <23.0.0` (`.nvmrc` 22.22.2) | Запуск API и тестов на 22.22.2 |
| fastify | 5.12.4 | Маршруты health отвечают вживую |
| pg | 8.23.0 | Транзакции и пул на PostgreSQL 16.13 |
| typescript | 7.0.2 | `tsc --noEmit` в strict, 0 ошибок |
| vitest | 5.0.1 | 2 unit + 8 integration PASS |
| tsx | 4.23.13 | Запуск API и команды миграций |
| @types/node | 22.20.2 | Соответствует линии Node 22, не 26 |
| @types/pg | 8.23.1 | — |

`tsc` используется только для проверки типов: код исполняется через `tsx`, сборка `tsc` не настроена и **эмиссия TypeScript 7 не проверялась**. Если позже понадобится собранный артефакт, это отдельная проверка, а не предположение.

Импорты внутри backend пишутся с расширением `.ts` (`allowImportingTsExtensions`), чтобы один и тот же исходник исполняли и `tsx`, и штатный Node 22.

Fastify 5.12.4 объявляет `disableRequestLogging` устаревшей опцией верхнего уровня (удаление в 6). Не используется: `logger: false` выключает логирование целиком.

## P0-01b: выполненные проверки

Среда проверки отличалась от аудита P0-01a: Node 22.22.2, npm 10.9.7, Python 3.11.15, клиент psql 16.13, Docker CLI без работающего демона. Поэтому тестовый PostgreSQL поднимался локальным кластером (`initdb` + `pg_ctl`, порт 5433), а не контейнером.

```bash
npm install                                    # 108 пакетов, 0 уязвимостей, lockfile создан
npm run typecheck                              # PASS, strict, 0 ошибок
npm test                                       # PASS: 2 unit
DATABASE_URL=... npm run test:integration      # PASS: 8 integration на реальной БД
DATABASE_URL=... npm run migrate               # применено 0, ранее применено 0
python3 docs/validation/check_architecture.py  # PASS: 19 файлов, 217 ссылок, 77/32
```

Живые проверки запущенного API (`npm run dev`, curl):

| Проверка | Результат |
|---|---|
| `GET /health` | 200, `{"status":"ok"}`, без обращения к БД |
| `GET /health/ready` при доступной БД | 200, `{"status":"ready","database":"up"}` |
| `GET /health/ready` при недоступной БД | 503, `{"status":"not_ready","database":"down"}` |
| Процесс после отказа БД | Жив, liveness продолжает отвечать 200 |

Интеграционные проверки БД: commit фиксирует данные; ошибка внутри транзакции откатывает их и пробрасывает исходную ошибку; 15 подряд неудачных транзакций не исчерпывают пул; миграции применяются по порядку имён; повторный прогон не применяет ничего; изменение применённого файла отклоняется по SHA-256; упавшая миграция не оставляет ни записи в ledger, ни созданной таблицы.

**Границы этих результатов.** PostgreSQL 16.13 в одноразовой Linux-среде, пустая тестовая база, один процесс. Это не проверка развёрнутого окружения и не нагрузочная проверка.

**Подтверждено на целевом сервере (2026-09-16).** PostgreSQL 18.6, npm 12, запуск от root: `typecheck`, 26 проверок без базы и 149 интеграционных прошли полностью. Схема, политики RLS с `FORCE`, `FOR UPDATE SKIP LOCKED` и составные внешние ключи работают на 18-й версии так же, как на 16-й.

## Незакрытый gate: iOS

`swift` и `xcodebuild` отсутствуют, среда Linux. Не выполнены и не могут быть выполнены здесь: минимальная сборка SwiftUI-приложения, фиксация версий Xcode/Swift/SDK/GRDB, deployment target iOS 17+.

**Поэтому весь P0-01 не завершён.** Отмечать его готовым можно только после сборки на Mac. Backend-часть P0-01b закрыта.
