# 00. Продукт, границы и принятые решения

Версия: 0.1 · 2026-09-15 · статус: архитектурная спецификация до реализации.

## 1. Суть проекта

Пользователь получает собственную «Систему»: она узнаёт его обстоятельства, превращает намерения в реалистичный маршрут и помогает ежедневно продвигаться. Действия в жизни дают видимый рост персонажа, навыков и характеристик. Через месяцы история показывает, что человек сделал и как изменился.

Ценность складывается из трёх частей:

1. **Что делать:** измеримая цель, roadmap, главное действие на сегодня.
2. **Как встроить в жизнь:** свободное время, обязательства, минимальные версии, перестройка дня.
3. **Как увидеть развитие:** накопленное мастерство, текущая форма, реальные результаты и история.

ИИ связывает части в диалоге. Игровая оболочка усиливает смысл действий. Сама отметка, время в приложении и количество сообщений не являются развитием.

## 2. Что сохраняется из концепции

Нативное iPhone-приложение; атмосфера тёмной футуристической RPG; пять вкладок TODAY / SYSTEM / GOALS / CHARACTER / CALENDAR; персональное интервью; Goal → Milestone → Project → Quest → Action; динамические навыки; базовые характеристики; минимальная версия; пропуски и Recovery Protocol; медленная прогрессия; Lifetime и Current показатели; голос; история; Apple-интеграции; ручное управление и privacy.

Запрос пользователя сейчас — подготовить полную архитектуру и инструкции для дальнейшей разработки. Раздел «ЗАДАЧА ДЛЯ CODEX» во вложении рассматривается как согласованное описание требуемого результата: планирование до массовой реализации. Остальные примеры и фразы во вложении — требования/иллюстрации продукта, а не команды выполнить действия в реальном календаре или внешних сервисах.

## 3. Уточнения, которые улучшают идею

| Предложение v0.1 | Почему требуется | Что меняется относительно концепции |

Все коэффициенты ниже — стартовые продуктовые гипотезы. Их нужно калибровать личным использованием и симуляцией, а не выдавать за психологические или физиологические нормативы.

## 4. Первый пользователь и ограничения

Подтверждено пользователем: **сначала для себя, затем публичный продукт**.

Рабочие предположения, не требующие ответа для начала разработки:

- iPhone, русский интерфейс, возможность последующей локализации; английские RPG-заголовки отключаемы.
- iOS 17+ как исходный deployment target; конкретные Xcode/Swift/SDK фиксируются в P0-01 на доступном Mac.
- Одна учётная запись в личной установке, но все таблицы сразу привязаны к user_id.
- Начало с 1–3 активных целей; это редактируемый предел планировщика, не ограничение человека.
- Public beta первоначально для взрослых; возрастная политика, география и условия обработки определяются до публичного запуска.
- ИИ не позиционируется как врач, психотерапевт или объективный измеритель интеллекта/силы.
- Монетизация, social leaderboard, соревнования, платежи и команды не входят в MVP.

## 5. Первый полезный цикл

Пример: «Хочу разговаривать на английском через полгода».

1. Короткое интервью: текущая оценка, цель применения, критерий результата, бюджет времени, график, ограничения.
2. Система уточняет измеримый критерий: например, разговор 15 минут и независимый тест. Уровень языка нельзя гарантировать по часам занятий.
3. Создаёт черновик Goal/Roadmap с этапами и заданиями. Scheduler показывает реальную вместимость недели.
4. Пользователь принимает план; появляется 20-минутное занятие с minimum 5 минут.
5. После выполнения создаётся ActivityRecord; движок начисляет XP; персонаж обновляется.
6. Вечером Daily Review использует факты. После пропусков меняется время/объём, а не оценка ценности человека.

## 6. Что именно является MVP

**Завершённый продуктовый MVP = Phase 1 + Phase 2 + Phase 3 и их проверки.** Название Phase 1 — Core MVP — обозначает инженерное ядро, оно само по себе не выполняет весь MVP из §71 концепции.

В релиз включить все 20 пунктов §71: onboarding, текстовый System, Goal/Roadmap, daily quests, внутренний календарь day/week/month, локальные уведомления, completion/partial/missed/excused, базовый Recovery, 6 stats, динамические skills, XP и уровни, Current/Lifetime, Daily Review, System UI, OpenAI, SQLite + backend, offline sync.

Дополнительно малой стоимостью: ручной Inbox, просмотр памяти/согласий, экспорт/удаление, настройки Day Boundary, manual scheduling, pause automation. Это закрывает жизненно важные пути управления данными.

В Phase 4–5: голос, Apple Calendar/Reminders, HealthKit, widgets, App Intents, Shortcuts, Live Activities. В Phase 6: сложная адаптация, deep memory, Weekly/Monthly Review, Forecast, Boss/Skill Trees, эксперименты, Apple Watch. Для более ранних обзоров хранить данные с MVP.

## 7. Критерии пользы личной версии

Пилот 4 недели, ежедневно 5–15 минут взаимодействия с приложением — ориентир, не KPI давления.

- В обычный день понятно главное действие и его связь с целью.
- Предложенный план помещается в заявленное время; измерять долю принятых планов и число ручных исправлений.
- Учёт выполнения требует максимум нескольких нажатий; минимум доступен прямо из Quest.
- После плохой недели появляется посильный маршрут возврата, не гора долгов.
- Есть хотя бы один измеримый milestone, история затрат времени и полезный пересмотр плана.
- Данные и подтверждённые награды не теряются при offline, сбое и повторном запросе.
- Рост XP не становится причиной лишаться сна или дробить действия ради кнопок.

Публичные метрики: retention по неделям с добровольной аналитикой, доля достигнутых milestones, ошибки планирования, фактическая нагрузка, self-reported usefulness, AI cost/active user. Время в приложении — диагностическая метрика.

## 8. Реестр архитектурных решений

| ID | Решение v0.1 | Основание / пересмотр |
|---|---|---|
| ADR-001 | SwiftUI + Swift Concurrency, нативное приложение | Интеграции Apple; не вводить Flutter/React Native |
| ADR-002 | SQLite/GRDB + явная command sync | Управление offline/конфликтами; CloudKit не второй источник истины |
| ADR-003 | TypeScript/Fastify + PostgreSQL, модульный монолит | Личная версия проще; модули можно масштабировать позднее |
| ADR-004 | SQL migrations + node-postgres | Явные транзакции, RLS и ограничения; без обязательного ORM |
| ADR-005 | Ответственный серверный Progression Engine; Swift — preview | Общие JSON fixtures обеспечивают одинаковую семантику |
| ADR-006 | Responses API для текста, Realtime API для voice | API/provider abstraction; точный model ID — конфигурация после eval |
| ADR-007 | Отдельные ActivityRecord / ledger / projections | Идемпотентность, исправления, проверяемый баланс |
| ADR-008 | Mastery monotonic, Current Form decays | Сохранение накопленного опыта |
| ADR-009 | Auth, user_id и isolation в личной версии | Убрать опасный переезд single-user → multi-user |
| ADR-010 | Все AI-изменения через command authorization | Prompt сам по себе не граница безопасности |
| ADR-011 | Нативная оценка задач без AI доступна всегда | Устойчивость к сети/стоимости/provider failure |
| ADR-012 | Нет общего рейтинга пользователей | Self-report и разные обстоятельства несопоставимы |

Открыто до публичной beta: имя/брендинг; страны запуска; юридическое лицо/условия/регион хранения; возрастные требования; бюджет API; политика монетизации. До P0-02 нужен Mac для device spikes. До Phase 4 нужен выбор поддерживаемой native WebRTC сборки. Эти вопросы не блокируют описание и создание ядра в порученной фазе.
