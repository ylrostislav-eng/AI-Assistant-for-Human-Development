# Прототип сессий: ротация и обнаружение кражи (часть P0-04)

Дата: 2026-09-15. Проверяются параметры из [09. Безопасность](09-security-and-operations.md), раздел 2: refresh со сроком 30 дней и ротацией, хранение хеша на сервере, отзыв семьи сессий, обнаружение повторного использования.

Это spike: пользователь задаётся синтетическим идентификатором, проверка Apple identity token относится к P1-02. Код — `services/backend/spikes/session-rotation/`, запуск `npm run test:spikes`.

## Найденная ошибка

Первая версия обнаруживала повторное использование так: внутри транзакции отзывала семью сессий и оттуда же бросала исключение. Снаружи поведение выглядело правильным — вызов возвращал ошибку «повторное использование». Но исключение откатывало транзакцию **вместе с отзывом**, поэтому украденный и настоящий токены продолжали работать.

Это худшая разновидность ошибки безопасности: защита сообщает о срабатывании и при этом не срабатывает. По журналам всё выглядит так, будто кража пресечена.

Ошибку нашла проверка, которая после обнаружения кражи пробует действующий токен настоящего владельца. Проверка только на то, что «предъявление старого токена вернуло ошибку», прошла бы и на сломанной версии.

Исправление: транзакция возвращает признак повторного использования, а исключение бросается после её фиксации.

## Проверенное поведение

| Проверка | Результат |
|---|---|
| Сервер хранит хеш, а не токен | PASS |
| Срок refresh — 30 дней | PASS |
| Ротация выдаёт новый токен и гасит предъявленный | PASS |
| Неизвестный токен отклонён | PASS |
| Истёкший токен отклонён | PASS |
| Токен одного пользователя не даёт сессию другого | PASS |
| Повторное использование отзывает всю семью, включая действующий токен владельца | PASS |
| Кража на одном устройстве не трогает семьи других устройств | PASS |
| После отзыва семьи токен не работает | PASS |
| Два одновременных обновления одним токеном не дают двух действующих | PASS |

Время передаётся параметром: иначе проверка срока потребовала бы ждать 30 дней или подменять системные часы. Строка сессии берётся `FOR UPDATE` — без блокировки гонка двух обновлений выдала бы два действующих токена, и украденный остался бы рабочим.

## Открытый вопрос для P1-02

Строгое обнаружение повторного использования не отличает похитителя от клиента, который повторил запрос после обрыва сети: обоих ждёт отзыв семьи, то есть выход из аккаунта. Обычное решение — короткое окно допуска, когда повтор того же токена возвращает уже выданный результат вместо отзыва. Здесь оно намеренно не введено, чтобы поведение было явным и решение принималось осознанно, вместе с политикой повторов клиента.

## Что не проверено

Проверка Apple identity token, выпуск и срок access-токена, привязка к устройству и отзыв устройства из интерфейса, расхождение часов между серверами, поведение при нескольких экземплярах приложения за общим пулом соединений. Прототип не является модулем identity и не подключён к API.
